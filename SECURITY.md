# Security Policy

## Reporting a vulnerability

Please report vulnerabilities privately through the repository's GitHub Security
Advisories page. Do not open a public issue containing an exploit, sensitive data,
or a working proof of concept before the maintainer has had a reasonable opportunity
to investigate.

Include the affected component, reproduction conditions, expected security property,
observed behavior, and the smallest safe reproduction you can provide. Reports about
generated output should also include the selected language, layers, runtime version,
and original benign fixture.

## Scope

Security reports may cover the hosted application's client-side behavior, dependency
risks, unsafe transformation behavior, unintended data transmission, and repository
or deployment configuration. The project does not guarantee that generated output is
undetectable or compatible with every runtime; a security product detecting generated
code is not by itself a vulnerability.

Only test systems and code you own or are explicitly authorized to assess.
